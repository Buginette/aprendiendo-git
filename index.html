3.1 Ramas

Una rama es un puntero a un commit: trabajo en paralelo sin tocar main.

git switch -c feature/nueva-idea

3.2 Fusiones e integración en Git

Durante esta práctica aprendí cuatro técnicas para integrar cambios entre diferentes ramas.

Fusión de tres vías

Permite combinar ramas divergentes y conservar sus respectivos historiales mediante un commit de fusión.

git merge --no-ff feature/fusion-3-vias

Fusión No Fast-Forward

Genera un commit de fusión y permite visualizar la integración de una rama en el historial.

git merge --no-ff feature/fusion-no-ff

Fusión Squash

Permite reunir varios cambios de una rama en un único commit de la rama principal.

git merge --squash feature/fusion-squash

Integración mediante Rebase

Reorganiza los commits de una rama sobre otra, creando un historial más lineal.

git rebase main

Resultado de la práctica

Aprendí a utilizar diferentes estrategias de integración y a revisar el historial mediante git log.

3.3 Resolución de conflictos en Git

Durante esta práctica aprendí a identificar y resolver conflictos al trabajar con diferentes ramas de Git.

Conflictos con Merge

Modifiqué el subtítulo de mi página desde dos ramas diferentes. Utilicé Git Merge para detectar el conflicto y Visual Studio Code para resolverlo.

Conflictos con Rebase

Realicé cambios diferentes en los colores de los títulos de mi página y utilicé Git Rebase para reorganizar el historial y resolver el conflicto.

Aprendizaje obtenido

Comprendí la importancia del control de versiones, la colaboración y la resolución de conflictos durante el desarrollo de proyectos.

3.4 Historial y recuperación

Usé log y diff para revisar versiones, revert para deshacer un cambio, reset y reflog para recuperar commits, y stash para guardar trabajo temporalmente.

git reflog
